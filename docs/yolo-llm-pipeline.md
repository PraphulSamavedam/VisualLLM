# YOLO + LLM Pipeline Architecture

## Overview

The YOLO + LLM pipeline combines real-time object detection with large language models to perform Visual Question Answering (VQA). This approach leverages YOLOv5 (You Only Look Once) to detect and localize objects in images, providing detailed object information as context for LLMs (Llama-2 or Mistral) to answer questions about the images.

## Component Details

### 1. YOLOv5 Object Detection

YOLO (You Only Look Once) is a real-time object detection framework that processes images in a single forward pass. YOLOv5 provides:

- **One-stage detection**: Direct prediction of bounding boxes and class probabilities
- **Real-time performance**: Fast inference suitable for production systems
- **Rich object information**: Class labels, positions, and confidence scores

**Model Used**: YOLOv5 pre-trained on COCO dataset

**Detection Output Format**:
```
object_name (confidence_score), object_name (confidence_score), ...
```

**Example Output**:
- Input: Image of children sleeping
- Output: "person (0.95), person (0.92), bed (0.89), pillow (0.82), pillow (0.80), blanket (0.76)"

### 2. Object Detection Processing

The detection results are formatted as a comma-separated list containing:
1. **Object class names**: Identified object types
2. **Confidence scores**: Detection confidence (0-1 range)
3. **Implicit spatial information**: Order in list may reflect importance

### 3. LLM Processing

Two LLM variants are supported:
- **Llama-2-7b-chat-hf**: Meta's conversational model
- **Mistral-7B-Instruct-v0.2**: Mistral AI's instruction-following model

Both models process the structured object detection data to answer questions.

## Prompt Templates

The pipeline implements four different prompt configurations with YOLO detections:

**Purpose**: Baseline performance with object detections

## Data Flow

1. **Input Preparation**
   - Load question-answer pairs from sampled dataset
   - Load pre-computed YOLO detections
   - Each detection contains object classes and confidence scores

2. **Model Initialization**
   - Set up device (CUDA/CPU)
   - Clear GPU cache for optimal memory usage
   - Load LLM pipeline (Llama or Mistral)
   - Configure generation parameters

3. **Inference Loop**
   - For each image-question pair:
     - Retrieve YOLO detections
     - Construct prompt with specific template
     - Generate answer using LLM
     - Store results with metadata

4. **Output Storage**
   - Save results to CSV files
   - Maintain different files for each configuration
   - Preserve image ID, detections, question, prompt, and answer

## Object Detection Format

### Detection String Structure

YOLO generates detections in the format:
```
class_name (confidence), class_name (confidence), ...
```

**Example Detections**:
```
person (0.95), person (0.92), bed (0.89), pillow (0.82), pillow (0.80)
```

### Information Encoded

1. **Object Classes**: Types of objects present (person, bed, pillow)
2. **Confidence Scores**: Detection reliability (0-1 range)
3. **Object Counts**: Implicit through repetition (2 persons, 2 pillows)
4. **Relative Importance**: Higher confidence suggests more prominent objects

### LLM Understanding

The LLM learns to:
- Count objects by tallying repeated class names
- Assess object presence based on class labels
- Infer scene context from object combinations
- Handle ambiguous detections using confidence scores

## Strengths

1. **Excellent for Counting**: Direct object counts from detection list
   - Example: "How many people?" → Count "person" in detections
2. **Object Presence Queries**: Easy to verify if specific objects exist
   - Example: "Is there a bed?" → Search for "bed" in detections
3. **Structured Data**: LLM receives clean, formatted object information
4. **Precise Object Information**: Captures all detected objects, not just scene-central ones
5. **High Accuracy for Object Questions**: Best exact match accuracy (0.471) for Llama

## Limitations

1. **Scene Context Missing**: No holistic scene understanding
   - Cannot answer "What is the mood?" or "What is happening?"
2. **No Relationships**: Doesn't capture spatial or semantic relationships
   - Cannot answer "Where is X relative to Y?"
3. **Activity Recognition**: Poor at understanding actions or events
4. **Attribute Questions**: Cannot determine colors, textures, or object states
5. **Abstract Concepts**: Struggles with non-object-based questions

### Example Failure Cases

**Question**: "What emotion is shown in the image?"
- **Detection**: "person (0.95), bed (0.89)"
- **Issue**: No emotion or expression information in detections

**Question**: "What are the people doing?"
- **Detection**: "person (0.95), person (0.92)"
- **Issue**: No activity or action information captured

## Use Cases

**Best suited for:**
- Object counting questions ("How many X are there?")
- Object presence queries ("Is there a Y?")
- Identifying visible objects ("What objects are in the image?")
- Questions requiring precise object information

**Not recommended for:**
- Mood/emotion questions ("What emotion is shown?")
- Activity recognition ("What is happening?")
- Spatial relationships ("Where is X?")
- Abstract scene understanding ("What type of event is this?")

## Technical Considerations

### Memory Management

```python
# Clear GPU cache before processing
torch.cuda.empty_cache()
```

This is crucial for YOLO + LLM pipeline as:
- YOLO detections are pre-computed (memory efficient)
- Only LLM needs to be loaded in GPU memory
- Prevents out-of-memory errors during batch processing

### Batch Processing

The implementation processes instances one at a time using list comprehension:
```python
answers = [{
    'Image ID': instance['Image ID'],
    'Detections': instance['Generated Detections'],
    'Question': instance['Question'],
    'Prompt': instance['Prompt'],
    'Generated Answer': llamaPipe(instance['Prompt'],
                                   max_new_tokens=3)[0]['generated_text']
} for _, instance in tqdm(df.iterrows())]
```

Benefits:
- Progress tracking with tqdm
- Resilient to individual failures
- Memory-efficient for large datasets
