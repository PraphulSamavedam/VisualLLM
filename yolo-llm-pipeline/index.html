    YOLO + LLM Pipeline Architecture¶

    Overview¶

    The YOLO + LLM pipeline combines real-time object detection with large language models to perform Visual Question Answering (VQA). This approach leverages YOLOv5 (You Only Look Once) to detect and localize objects in images, providing detailed object information as context for LLMs (Llama-2 or Mistral) to answer questions about the images.

    Component Details¶

    1. YOLOv5 Object Detection¶

    YOLO (You Only Look Once) is a real-time object detection framework that processes images in a single forward pass. YOLOv5 provides:

    • One-stage detection: Direct prediction of bounding boxes and class probabilities
    • Real-time performance: Fast inference suitable for production systems
    • Rich object information: Class labels, positions, and confidence scores

    Model Used: YOLOv5 pre-trained on COCO dataset

    Detection Output Format: 

    object_name (confidence_score), object_name (confidence_score), ...

    Example Output: - Input: Image of children sleeping - Output: "person (0.95), person (0.92), bed (0.89), pillow (0.82), pillow (0.80), blanket (0.76)"

    2. Object Detection Processing¶

    The detection results are formatted as a comma-separated list containing: 1. Object class names: Identified object types 2. Confidence scores: Detection confidence (0-1 range) 3. Implicit spatial information: Order in list may reflect importance

    3. LLM Processing¶

    Two LLM variants are supported: - Llama-2-7b-chat-hf: Meta's conversational model - Mistral-7B-Instruct-v0.2: Mistral AI's instruction-following model

    Both models process the structured object detection data to answer questions.

    Prompt Templates¶

    The pipeline implements four different prompt configurations with YOLO detections:

    Configuration 1: Default (20 tokens)¶

    Purpose: Baseline performance with object detections

    df["Prompt"] = "Based on the Object detections (generated by YOLOv5): '" \
                + df["Generated Detections"] + "', Answer the question '" \
                + df["Question"] + "' \n Answer: "

answers = [{

} for _, instance in tqdm(df.iterrows())]

    Data Flow¶

    1. Input Preparation
    2. Load question-answer pairs from sampled dataset
    3. Load pre-computed YOLO detections

    4. Each detection contains object classes and confidence scores

    5. Model Initialization

    6. Set up device (CUDA/CPU)
    7. Clear GPU cache for optimal memory usage
    8. Load LLM pipeline (Llama or Mistral)

    9. Configure generation parameters

    10. Inference Loop

    11. For each image-question pair:

      • Retrieve YOLO detections
      • Construct prompt with specific template
      • Generate answer using LLM
      • Store results with metadata

    12. Output Storage

    13. Save results to CSV files
    14. Maintain different files for each configuration
    15. Preserve image ID, detections, question, prompt, and answer

    Object Detection Format¶

    Detection String Structure¶

    YOLO generates detections in the format: 

    class_name (confidence), class_name (confidence), ...

    Example Detections: 

    person (0.95), person (0.92), bed (0.89), pillow (0.82), pillow (0.80)

    Information Encoded¶

    1. Object Classes: Types of objects present (person, bed, pillow)
    2. Confidence Scores: Detection reliability (0-1 range)
    3. Object Counts: Implicit through repetition (2 persons, 2 pillows)
    4. Relative Importance: Higher confidence suggests more prominent objects

    LLM Understanding¶

    The LLM learns to: - Count objects by tallying repeated class names - Assess object presence based on class labels - Infer scene context from object combinations - Handle ambiguous detections using confidence scores

    Strengths¶

    1. Excellent for Counting: Direct object counts from detection list
    2. Example: "How many people?" → Count "person" in detections
    3. Object Presence Queries: Easy to verify if specific objects exist
    4. Example: "Is there a bed?" → Search for "bed" in detections
    5. Structured Data: LLM receives clean, formatted object information
    6. Precise Object Information: Captures all detected objects, not just scene-central ones
    7. High Accuracy for Object Questions: Best exact match accuracy (0.471) for Llama

    Limitations¶

    1. Scene Context Missing: No holistic scene understanding
    2. Cannot answer "What is the mood?" or "What is happening?"
    3. No Relationships: Doesn't capture spatial or semantic relationships
    4. Cannot answer "Where is X relative to Y?"
    5. Activity Recognition: Poor at understanding actions or events
    6. Attribute Questions: Cannot determine colors, textures, or object states
    7. Abstract Concepts: Struggles with non-object-based questions

    Example Failure Cases¶

    Question: "What emotion is shown in the image?" - Detection: "person (0.95), bed (0.89)" - Issue: No emotion or expression information in detections

    Question: "What are the people doing?" - Detection: "person (0.95), person (0.92)" - Issue: No activity or action information captured

    Use Cases¶

    Best suited for: - Object counting questions ("How many X are there?") - Object presence queries ("Is there a Y?") - Identifying visible objects ("What objects are in the image?") - Questions requiring precise object information

    Not recommended for: - Mood/emotion questions ("What emotion is shown?") - Activity recognition ("What is happening?") - Spatial relationships ("Where is X?") - Abstract scene understanding ("What type of event is this?")

    Technical Considerations¶

    Memory Management¶

    # Clear GPU cache before processing
torch.cuda.empty_cache()

    This is crucial for YOLO + LLM pipeline as: - YOLO detections are pre-computed (memory efficient) - Only LLM needs to be loaded in GPU memory - Prevents out-of-memory errors during batch processing

    Batch Processing¶

    The implementation processes instances one at a time using list comprehension: 

    answers = [{
    'Image ID': instance['Image ID'],
    'Detections': instance['Generated Detections'],
    'Question': instance['Question'],
    'Prompt': instance['Prompt'],
    'Generated Answer': llamaPipe(instance['Prompt'],
                                   max_new_tokens=3)[0]['generated_text']
} for _, instance in tqdm(df.iterrows())]

    Benefits: - Progress tracking with tqdm - Resilient to individual failures - Memory-efficient for large datasets

    Future Improvements¶

    1. Spatial Information: Include bounding box coordinates in prompts
    2. Confidence Thresholding: Filter low-confidence detections
    3. Object Relationships: Add spatial relationship extraction
    4. Hierarchical Object Structure: Group objects by semantic relationships
    5. Enhanced Detection Format: Include object attributes (color, size, orientation)
    6. Model Selection: Investigate why Mistral underperforms with YOLO data
    7. Prompt Engineering: Develop specialized prompts for object-centric questions

    Best Practices¶

    1. Use Llama-2: Significantly better performance than Mistral for YOLO detections
    2. Enable Token Limiting: Use max_new_tokens=3 for single-word answers
    3. Add Prompt Instructions: Include explicit single-word answer requirement
    4. Pre-compute Detections: Run YOLO offline to optimize inference time
    5. Monitor GPU Memory: Clear cache before processing large batches
    6. Question Analysis: Route object-centric questions to YOLO pipeline
